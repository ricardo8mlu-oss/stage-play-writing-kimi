# 项目流程：只推进当前需要的一步

## 路线

1. **项目边界**：明确观众、演出情境、目标时长、演员配置、空间、技术与材料来源。若是命题创作，标出必须出现的事件、人物和表达要求。
2. **戏核**：写成一句可争夺的行动：主角要做什么，对手为何阻止，失败的具体代价是什么。再说明主题倾向；主题是观众从行动及结果中读出的判断，不是角色轮流宣讲的口号。
3. **人物与结构**：列每个人的目标、手段、关系、限制和选择代价；排出能改变局面的因果转折，再决定幕场边界。先有选择链，再定是否采用三幕、起承转合或其他形式。
4. **分场**：逐场记入场状态、各方行动、反制、转折、出场状态。只写在舞台上会发生或让观众能感知的事。
5. **初稿**：从可表演的动作和对白写起。舞台提示描述可执行的状态与必要动作，把阐释留给冲突本身。
6. **改稿**：先查因果、人物动机与舞台可行性，再修对白、节奏和格式。全文读剧，记录实测时长、难以表演的段落和观众不明白的转折。
7. **交稿**：核对角色名单、兼演、场景、道具、音效、危险动作、事实与虚构说明、文件可读性。若有竞赛或委托规则，以当前官方要求核对，不凭通用经验猜测。

用户只要一个场景、诊断或改编提案时，直接做该项；以上路线是检查遗漏用，不是强制交付七份材料。

## 续写已有项目

先读现稿和用户新要求，写极短的工作状态：已经固定的事实和创作约束、当前人物关系、悬而未决的因果、这一轮要动的场次。保存状态时只记会影响下一次创作的决定、版本与待核点；不要把整段聊天复制进“故事圣经”。

修改前保持人物称谓、事件顺序和已承诺的舞台条件一致。若想改动其中一项，应指出它会连带影响哪些场景。若用户要求多个时长版本，分别建立完整的行动线与结局，不能简单把长版机械删段当短版。

## 各阶段的通过问题

- 戏核：双方是否争同一件可见的事，失去的东西是否具体？
- 结构：后一场是否由前一场的选择或后果迫出？至少一个新选项消失了吗？
- 人物：主要角色是否有能力采取不同做法，却因动机与代价作出当前选择？
- 场景：每场是否有可表演的行动、局面变化和退场后果？
- 台词：这句话是否改变关系、争夺信息、执行策略或迫使回应？
- 排演：换景、兼演、道具传递、声音和时长是否在实际条件下可实现？
